# CLAUDE.md

Project-specific instructions for working in this repo.

## humansays — standing constraints

Full documentation: `docs/`. Start at `docs/process/agent-protocol.md`.
**Read only the phase file you are executing.**

## Never

1. **No runtime dependencies.** `rich` is an optional extra with an ANSI
   fallback. `deptry` enforces this.
2. **No `ast` or `tokenize` outside `humansays.analysis`.** `lint-imports`
   enforces this.
3. **Never import third-party code in order to analyze it.** Importing executes
   module-level code. Compile from disk or read `.pyc`.
4. **Nothing expensive on the scan path.** Call graphs, dependency summaries and
   dynamic runs produce cached artifacts; the static scan reads them.
5. **Observed evidence never enters an aggregate.** It is nondeterministic.
6. **Never claim** to be faster than Ruff, more comprehensive than Pylint, a
   replacement for type checking, able to prove runtime effects from syntax, or
   an objective definition of clean code.
7. **Never assert that code was generated by a model.** The tool detects
   narration structure. Authorship is not observable from structure.
8. **The operator owns git.** Do not commit, push, or branch unless asked.

## Always

9. **Every rule cites a criteria-document section**, and ships with a positive
   and a matched negative microfixture.
10. **`bug` means incorrect behavior or a language hazard.** Three rules carry it
    today. A fourth needs a cited language reference or a reproducible
    incorrect-behavior fixture — not a judgement call. The count is a fact, not
    a cap.
11. **Separate verified, inferred and unknown.** No performance claim without a
    before/after measurement. Numbers in `docs/evidence/` are measured — re-run
    them rather than re-deriving them.
12. **Stop when blocked.** Record the unresolved question. Never substitute an
    unverified theory.
13. **Every enforcement claim names its test.** If you write that something is
    blocked, prevented or guaranteed, name the test that proves it. This rule
    exists because the scope guard was documented as blocking changes it did not
    block.

## Not a metric

Rule count. The guards in `docs/design/02-evaluation-model.md` §5 are.

## Formatting and linting

Use the project's own scripts instead of invoking `ruff`/`ty`/etc. by hand:

- `scripts/format.sh` (or `make format`) — applies `ruff format` and
  `ruff check --fix --unsafe-fixes` in place. This is the only quality script
  that modifies repository files do not attempt to fix any linting issues without doing this first
- `scripts/lint.sh` (or `make lint`) — read-only: `ruff format --check`,
  `ruff check --no-fix`, `ty check`, `shellcheck`/`shfmt --diff`, `bandit`,
  `deptry`, `lint-imports --config .importlinter.ini`, `vulture`. Run
  `scripts/lint.sh <name>` for a single check (see the script's `main()` for
  the full list of subcommands).

Run `scripts/format.sh` before `scripts/lint.sh` when iterating locally,
rather than reasoning about individual `ruff`/`ty` invocations.
