# Security Policy

## supported versions

Only the latest released version and the default branch receive security
updates unless a release announcement states otherwise.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Default branch | Yes |
| Older releases | No |

## reporting a vulnerability

Do not open a public issue, discussion, or pull request for a suspected
vulnerability.

Use GitHub's private vulnerability reporting:

1. Open the repository's **Security** tab.
2. Select **Advisories**.
3. Select **Report a vulnerability**.

If private vulnerability reporting is unavailable, contact `SECURITY_CONTACT`.
Replace that placeholder before publishing this repository.

Include:

- the affected component and version,
- reproduction steps or a proof of concept,
- the expected security impact,
- any known mitigations,
- whether the issue has been disclosed elsewhere.

## response targets

Maintainers should acknowledge a report within three business days and provide
a status update within seven business days. These are targets, not guarantees.

Accepted reports should receive coordinated remediation and disclosure.
Declined reports should receive a brief explanation when doing so does not
create additional risk.
